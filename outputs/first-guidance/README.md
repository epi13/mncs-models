# Executed native direct-weight feasibility

**Result:** a five-parameter model was actually authored, executed and revised.
It selected a failing test first in **3/5** failure-bearing final groups, compared
with **2/5** initially and **3/5** for the informed deterministic rule. There is no
shown advantage over that rule. These cheap probes cost less native VM work than
the guidance, so this is not a deployment recommendation or a productivity claim.

three remain mandatory. The fixed independent criterion is a native assertion
against `(8,2,false)->6`, `(2,5,true)->3`, `(14,1,true)->12`. Pure implementation
modules s01..s06 form development; s07..s12 form exploratory evaluation. Module
source identities, not individual test rows, define the groups. Compilation is
batched; these are not twelve operational revisions or independent agent sessions.

## Genuine parameter authorship and native execution

Canonical `Model` 9301 has topology 4→1, no hidden layer, identity activation, and
five scale-one i64 parameters. This is not a proven minimum: activation also
gates candidates and the common bias cannot change ranking. Input lanes are activation, reference predicate
selection, reference downstream-clamp count, and earlier observed failures.
The source owner supplies a fixed region tag; native `reference.project_six`
computes observations. `select` is eager, so activation is selected value flow,
not CPU line coverage. History is `[2,3,1]` before final groups. No test name,
mutant identity, current verdict or current cost is a model input.

The explicitly authored initial vector is **[3,0,0,1,0]**, revision 1 / parent 0 /
provenance 9401. Two successful canonical `micro.edit` calls produce revision 2
**[3,2,0,1,0]** (parent 1, provenance 9402), then revision 3 **[3,2,-3,1,0]**
(parent 2, provenance 9403). `authorship.json`, Model ABI arguments and raw edit
results preserve every value. The first actual native selector call abstained on
s03 with **[4,4,3]**. Initial outputs, edits and regressions are retained. These
vectors were reasoned from permitted development observations, not generated by
an optimizer or reused from the older mechanical fixtures. There were **zero
weight edits after final outcomes**.

Development is exploratory: the first two pilot feature rows were reconstructed
post-outcome from the unchanged clean reference. A native replacement of the
initial transport projection reproduces every development feature value exactly.
Those rows are not claimed as historical pre-decision observations. Final
projection and prediction chronology is prospective with respect to execution.

bypass and unsupported cases make zero neural calls. The native four-item batch
reports one five-slot parameter check. It is lexical reuse, not a persistent
resident-service benchmark. Bypass inside the offline batch does not prove zero
model-loading/ABI cost: the batch already carries both Model values.

A single safe inference (524 VM steps) exceeds the **entire three-probe body** for
any final state (117–136 steps), even before feature/ranking overhead. Complete
selectors cost 2,929 steps for the informed rule and 4,511 for the learned scorer
on the same s07 input. The revised scalar arithmetic is tiny; admission, data and
selection work dominate. Both guarded selectors are excessive for these cheap
probes. All three tests remain required, so **zero required executions were saved**.
Earlier evidence is a valid ordering metric, not proof of fewer final tests.

Wall observations include CLI compilation/admission/cache and typed transport;
first and warmed paths differ. They are single descriptive observations under
concurrent development work, not isolated latency benchmarks. The 7.660 versus
7.637-second selector observations do not establish a wall-time advantage.
The final 18-test invocation took 9.130 seconds, but its batching/transport scope
differs from an individual selector. Do not infer causal agent savings from those
numbers. Peak memory, energy, physical I/O, a true resident interface, natural
context usefulness, and isolated LLM authoring tokens/time remain unmeasured.
Cumulative goal-service research accounting is stored separately.

## Native integration, authority and verification

Native source/reference projection → ordinary canonical Model/infer/edit → bounded
advisory selection → existing native TestReplayEvaluation is implemented. Native
Test executes all alternatives independently in fixed order; predictions do not
authorize or control live operations. No numerical primitive, graph runtime,
optimizer, telemetry service or general evaluation framework was added.

RAVEL's inspected experimental contracts include adaptive-evidence strategy and
verification-obligation planning. Its native planner owns compiler-impact/obligation/
test/evidence joining and freshness; task contexts refuse stale or unauthorized
requests. A future guide may consume its already-permitted inventory and evidence.
No RAVEL ranking output was used here, and no RAVEL/LSP parser or ranker was rebuilt.
`mncs-learn` retains learning/promotion governance; its inspected native operators
are centroid/no-learning, not a dense-weight optimizer. No operational model was
promoted. Opaque handles resolve through `reference-context.json`; they do not
constitute authenticated custody, permissions, or reliability proof.

The lasting `.mncs/environment.json` is now a general Models development definition,
with Models-only write scope. The old experiment-specific purpose and disabled
verification/actions/diagnostics/family passes were removed. Other repositories
remain read-only. Entry, exact claim and source authority observations are retained.

All **86 prior native tests pass**, plus **5 adapter guard tests**, for **91** total.
The guards check bypass with an invalid model, unknown context, future evidence,
score ties and unique relevance. The interrupted verification while moving the
projection and the repaired guard-source missing import remain explicit incomplete/
admission-failure evidence. They are not model evaluation failures or final PASS
receipts. Existing benchmark receipts and negative findings are unchanged.

## Reproduce without overwriting evidence

Run `python3 scripts/verify.py --output-root outputs/my-check` for all 91 tests.
The controlled defective suites are separate and intentionally return assertion
FAIL; they are not weakened green regression tests. Fresh development observations
can be collected with `python3 scripts/first_guidance.py develop --output-root
outputs/replayed-development`. Do not overwrite the published plan, models or raw
results.

For exact model/policy replay, invoke the recorded native command with its `.args.json`
and a new `--result` path, for example `mncs call
experiments/first_guidance/guidance.mncs --module study.guidance --function predict_six
--args outputs/first-guidance/evaluation-predictions.args.json --library src
--library experiments/first_guidance --result /tmp/first-guidance-replay.json`.
The binary/libraries are the admitted family toolchain recorded in the receipts.
`native-evaluation.args.json` contains the actual independent outcome matrix.
Native replay recomputed and exactly matched all frozen predictions, with all 30
policy/outcome comparisons accepted. `freeze.json`, `authorities.json`, raw native
results and the manifest bind source, model, compiler and experiment artifacts.

The conclusion is an executed, limited feasibility finding: a five-parameter
representation can use these observations, but the informed rule is equally useful
and cheaper in native work. No deployment or increase in model capacity is justified
by this cohort. See `docs/FIRST_GUIDANCE_FEASIBILITY.md` for the decision and ownership
assessment.
