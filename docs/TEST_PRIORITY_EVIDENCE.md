# Test-prioritization evidence after deterministic remediation

This campaign investigates earliest independently verified **test failure** among
already permitted tests. It does not turn a failing process into a diagnosis,
assume the historical first action was optimal, or remove required coverage.
The strongest inspected candidate is a complete same-source native test replay.
The available evidence does **not** yet establish an eligible learning cohort.

## Decision and utility, before choosing an architecture

1. **Question:** after source/readiness/authority checks, which of 2–8 relevant
   tests should run first to reveal an assertion failure early?
2. **Operations:** exact native Test selections, bound to source, compiler,
   libraries, test inventory and resource budget. Only the deterministic consumer
   executes them. Each operation retains its full native identity in the receipt.
3. **Permitted observations:** pre-decision changed source/dependency relationships,
   exact test identities, previous source-bound results/costs, readiness and budget.
   Current execution results are outcomes, never features for that execution.
4. **Baseline:** reuse an already verified identical subject when owner rules admit
   reuse; otherwise prefer exactly affected tests, then previously observed cost
   among equally relevant tests. The canonical `guide_operations` reproduces the
   unique least-cost step; ties retain its fallback. No random baseline is needed.
5. **Value:** an independently checked failure from the selected first test, and its
   measured cost relative to the cheapest failing alternative on the same source.
   A pass is useful verification work, but is not a discovered failure. All-pass
   states have no failure-discovery opportunity, rather than zero failure latency.
6. **Verification:** run every candidate against the same frozen source closure;
   keep native assertion result, execution identity and exact test selection. An
   outcome for an unexecuted diagnostic cannot be supplied by analogy.
7. **Costs:** structural/history acquisition, admission, feature encoding, model
   construction/revision/inference, independent tests and evidence recording are
   separate. VM steps, CLI wall time and agent time are separate units.
8. **Fallback:** preserve deterministic coverage when the decision is already
   resolved, identity/freshness/candidates change, observations are missing or
   contradictory, costs exceed budget, or demonstrated reliability is absent.

This is a candidate decision definition, not a claim that every verification run
contains a residual decision. Identical already-verified inputs are specifically
excluded from a learned target.

## Native support added for the observed evaluation gap

The existing actual-selection evaluator deliberately validates only the operation
that was actually selected. It cannot establish the relative value of competing
tests. The small extension to `trial.mncs` accepts a **complete** observed outcome
matrix for the existing `GuidanceProblem`; it is retrospective experiment support,
not a ranker, telemetry service, new model runtime or operational consumer.

The evaluator validates one row per exact candidate, source/event/state/question/
permitted-set joins, independent evidence handles, post-decision outcome chronology,
observed outcome kind, known native assertion verdicts and a single bounded cost
unit. A missing unchosen outcome refuses comparison. It reports first-choice failure
discovery and a retrospective cheapest-failing-test lower bound only when such a
failure exists. Mandatory execution count and total measured cost stay visible.
Predictions, Unknown verdicts, duplicate/foreign candidates and mixed costs refuse.
The external evidence owner must authenticate handles, freeze the exact dependency/
toolchain closure and establish outcome independence; native records cannot prove
custody or causal agent benefit. Summed VM steps do not predict order-dependent
compilation/cache wall time.

Mechanical tests use explicit artificial handles to test refusal/accounting only.
They are not additions to the operational learning cohort. The real-data adapter
only transports existing native Test results and costs into typed native calls;
all selection and replay evaluation remains MNCS. Event 1001 is a newly recorded
source-freeze experiment event, not a reconstructed historical agent decision.
Opaque handles resolve through the plan, reference context and result receipts.
Older receipts lack clock fields; their bytes are observed before this new plan,
rather than receiving invented historical availability times. New verification
receipts record host start/finish times, with their clock/custody limits explicit.

## Learning, information and capacity

The direct-weight trial remains conditional on actual eligible evidence. The unchanged baseline and subsequent support-extension source snapshot cannot
supply disjoint independent source-change training, development and held-out groups.
The final snapshot is recorded before its verification outcomes are read; that
chronology does not make it a sealed held-out learning trial. Existing verification receipts already reveal the unchanged baseline outcomes.
Re-running that baseline does not create a fresh unresolved decision or independent
examples. The new support extension supplies validation work, rather than a cohort
of independent naturally occurring product defects. Native fixture labels from earlier
synthetic experiments remain synthetic; they are not imported as real outcomes.

Structural identity and historical execution are complementary for **admission**:
identity determines whether a prior result can be reused; history supplies that
result and cost. Their deterministic combination must precede a model. Parameter
capacity cannot replace missing alternative outcomes, genuinely changed subjects
or an independent split. Small/large, single/multiview and composition utility
comparisons are therefore not estimable on this evidence. No direct-weight vector,
optimizer, specialist graph or live learned guide is manufactured to fill the gap.
The inspected `mncs-learn` native implementation still supplies centroid/no-learning
operators, not a dense-weight optimizer; its newer remote commits add coherence
metadata rather than that optimizer. Learning/promotion governance remains there.

The smallest additional evidence is several naturally occurring changed-source
states, each with a pre-decision permitted selection and structural/history views,
followed by all candidate native outcomes and costs under the same frozen closure.
Include all-pass, unknown and deterministic-bypass states in the denominator. A
separate evidence custodian must freeze an event-grouped chronological split before
an author sees held-out outcomes. Then author one minimal weight vector, freeze it,
evaluate once, and preserve a negative result. No new monitoring service is needed.
